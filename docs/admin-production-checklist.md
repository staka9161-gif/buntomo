# 管理・通報・安全機能 本番運用前チェックリスト

このドキュメントは、ブントモの管理者機能・通報機能・安全機能を本番で運用する前に、管理者が確認すべき項目を整理したものです。

実在ユーザーのメールアドレス、トークン、パスワード、DM本文全文は記録しないでください。実データで通報・停止・解除を試す場合は、対象ユーザーと影響範囲を事前に確認してください。

## 1. 本番確認の前提

- 本番URL: `https://buntomo.bunkare.jp`
- 管理者アカウントでログインして確認する項目があります。
- 未ログインHTTP確認だけでは、admin画面・通報操作・停止中ユーザー確認は完了しません。
- 確認結果は「実ログイン確認」「コード上確認」「HTTP確認」「未確認」を分けて記録してください。
- 本番DBを直接変更する確認は避けてください。
- 秘密情報、トークン、パスワード、フルメールアドレス、DM本文全文を記録しないでください。
- cron purge は破壊的な削除処理を含むため、安易に手動実行しないでください。

## 2. 基本ページ確認

以下のページについて、未ログイン時・通常ユーザー時・admin時の見え方を確認します。

- `/`
  - 未ログイン時: トップページが落ちずに表示される。
  - 通常ユーザー時: 通常導線が表示される。
  - admin時: 通常利用に支障がない。

- `/books/search`

  - 通常ユーザー時: 検索できる。
  - admin時: 検索できる。
- `/updates`
  - 未ログイン時: 更新のお知らせが表示される。
  - 通常ユーザー時: 表示順・リンクが自然である。
  - admin時: 通常ユーザーと同様に表示される。
- `/terms`
  - 未ログイン時: 利用規約が表示される。
  - 通常ユーザー時: 表示が崩れていない。
  - admin時: 表示が崩れていない。
- `/privacy`
  - 未ログイン時: プライバシーポリシーが表示される。
  - 通常ユーザー時: 表示が崩れていない。
  - admin時: 表示が崩れていない。
- `/admin`
  - 未ログイン時: `/login` に誘導される。
  - 通常ユーザー時: 管理画面が見えない。
  - admin時: 管理トップとサマリーが表示される。
- `/admin/users`
  - 未ログイン時: `/login` に誘導される。
  - 通常ユーザー時: 管理画面が見えない。
  - admin時: 利用者一覧が表示される。
- `/admin/reports`
  - 未ログイン時: `/login` に誘導される。
  - 通常ユーザー時: 管理画面が見えない。
  - admin時: 通報一覧が表示される。
- `/admin/audit-logs`
  - 未ログイン時: `/login` に誘導される。
  - 通常ユーザー時: 管理画面が見えない。

## 3. 通報機能確認

対象:

- ユーザープロフィール通報
- 本別チャット通報
- レビュー通報
- 読書会通報
- DM通報

チェック項目:

- 他人の対象には `通報` が表示される。
- 自分自身・自分の投稿・自分主催の読書会・自分が送信したDMには `通報` が表示されない。
- UIに表示されない対象は、API側でも拒否される。
- 同じ reporter が同じ対象へ pending / reviewing 通報を重複作成すると 409 になる。
- 通報作成時に通報相手へ通知されない。
- 通報対象の本文を `Report.detail` に複製していない。
- DM通報は、受け取ったDMのみ可能である。
- DM本文は管理者向けの短いプレビューのみ表示される。

## 4. 管理者通報対応確認

対象:

- `/admin/reports`
- `/admin/reports/[reportId]`

チェック項目:

- 未ログイン時は `/login` または 401 になる。
- 非adminでは権限なしになり、管理画面が見えない。
- adminは通報一覧・通報詳細を見られる。
- `targetType` フィルターが動く。
- `status` フィルターが動く。
- 通報詳細で status を変更できる。
- `resolved` / `rejected` へ変更する場合、管理者メモが必須になる。
- status変更で監査ログが残る。
- 通報詳細から対象ユーザー管理画面へ移動できる。
- 通報詳細に BAN / 停止ボタンが直接表示されていない。

## 5. ユーザー管理確認

対象:

- `/admin/users`
- `/admin/users/[userId]`

チェック項目:

- ユーザー検索が動く。
- 状態フィルターが動く。
  - `active`
  - `suspended`
  - `deactivated`
  - `scheduledDeletion`
- 通報フィルターが動く。
  - `hasReports`
  - `hasOpenReports`
- ユーザー詳細に通報サマリーが表示される。
- 最近の通報から通報詳細へ移動できる。
- 停止・停止解除が既存UIで動く。
- 自分自身や admin ユーザーを停止できない。
- 停止・停止解除が監査ログに残る。
- フルメール、認証情報、トークン類が表示されない。

## 6. 停止中ユーザー制限確認

確認対象:

- 友だち申請作成
- 友だち申請承認・拒否・取消
- 友だち解除
- block / unblock
- DM送信
- 本別チャット投稿
- レビュー投稿
- 読書会作成・編集・削除
- 読書記録作成・更新・削除
- プロフィール更新
- プロフィール画像更新
- 通知設定更新
- 通報作成
- Work統合候補投稿
- bookshelf登録

チェック項目:

- 未ログイン時は 401 になる。
- 停止中ユーザーは 403 になる。
- active user は既存どおり操作できる。
- GET / read-only API は必要以上に止めていない。

## 7. DM・プライバシー確認

- DM本文が一般APIに漏れていない。
- `/api/admin/stats` にDM本文・DMプレビューが出ていない。
- `/api/admin/users` にDM本文・DMプレビューが出ていない。
- `/api/admin/audit-logs` にDM本文・DMプレビューが出ていない。
- `/api/admin/reports` と `/api/admin/reports/[reportId]` のみ、管理者向けに短いDMプレビューを返す。
- `/terms` と `/privacy` に、通報対応時に必要な範囲で内容を確認する場合がある旨の説明がある。

## 8. 監査ログ確認

対象:

- `/admin/audit-logs`
- `/api/admin/audit-logs`

チェック項目:

- 未ログイン時は 401 または `/login` になる。
- `action` フィルターが動く。
- `targetType` フィルターが動く。
- `adminUserId` フィルターが動く。
- `targetUserId` フィルターが動く。
- 対象リンクが動く。
  - Report
  - User
- metadata が安全に表示される。
- `content` / `body` / `message` / `text` / `dm` / `email` / `token` / `password` 系 key が非表示になる。
- 監査ログの削除・編集APIがない。

## 9. 退会・削除予定・cron確認

- 退会で `deactivatedAt` と `scheduledDeletionAt` が設定される。
- 30日以内にログインすると復帰できる設計である。
- cron purge は `deactivatedAt != null` かつ `scheduledDeletionAt <= now` のみ削除対象にする。
- cron purge には `CRON_SECRET` が必要である。
- User削除前に `LearningSignal.userId` を null にしている。
- purge を手動実行する場合は本番DBに影響するため、事前に対象件数と条件を確認する。
- `prisma migrate reset` や本番DBへの不用意な `db push` は実行しない。

## 10. `/updates` 確認

- ユーザー向け変更が掲載されている。
- 管理者向け内部変更を載せすぎていない。
- 直近で追加された通報関連のお知らせが表示されている。
  - プロフィール通報
  - チャット通報
  - レビュー・読書会通報
  - 通報対応説明
  - DM通報
- 表示順と文言が自然である。
